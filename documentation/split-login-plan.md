# Separate login interfaces

User login remains at `/login`; existing admin-role accounts also use this page so their accounting administration is not removed. Super Admin uses `/super-admin/login` and lands at `/super-admin`. User/admin successful login lands at `/dashboard`; user company setup remains available through the native company link. `/register` remains standard-user-only and controlled by the existing public_registration_enabled flag, OFF by default. Do not silently enable public registration or add Super Admin signup.

Reuse existing Flask sessions, password hashes, login audit and in-app throttling through one shared authentication function. Each portal enforces allowed roles on the server; a submitted role or redirect target cannot choose privileges/destination. Native HTML forms use existing CSRF session token; compatibility JSON responses keep user/csrf_token fields and add fixed redirect_url. Failed wrong-role/invalid/inactive/deleted credentials clear prior authentication and create no authenticated session or successful-login audit. Both portals share one cookie/database, not duplicate auth systems; one account per browser session, use private window for simultaneous accounts.

Existing auth/login template and protected-area redirects need scoped edits. New Super Admin login template extends the same native card/CSS, with Arabic RTL labels and empty credentials. New pages do not load financial JavaScript. Registration links appear only on user login when enabled; no registration entry appears on Super Admin login. Form signup returns to user login. Native logout returns to the appropriate portal.

No schema/migration/new database/dependency/domain/repository/hosting changes. Original financial routes/models/calculations and portfolio content untouched; dashboard logout alone must follow verified role-specific server destination. New tests cover both role gates, native forms/CSRF, fixed destinations, privacy, flags, wrong credentials/revocation and actual isolated Windows launcher imports. Historical preservation manifests remain; add transparent authorized login-interface overlay. Push to the existing main after regression checks and independently open the commit.
